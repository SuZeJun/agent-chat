# Agent Chat 产品简述

## 1. 文档目的

本文档定义项目的产品方向、目标用户、核心价值和成功标准。项目名称 `Agent Chat` 为工作名，后续可以在不改变产品定位的前提下调整。

## 2. 一句话定位

Agent Chat 是一个面向企业客服与技术支持团队的 AI 服务运营平台：它基于企业知识生成可追溯回答，通过 Eino 编排工具调用与人工确认，在低置信度、高风险或客户主动要求时将会话平滑转交人工。

## 3. 业务边界

本项目不将自己限定为纯 B2B 产品。

- 采购、部署和运营方通常是企业。
- 客服工作台的直接用户是企业客服、技术支持和管理员。
- 聊天入口的终端用户既可能是个人消费者，也可能是企业客户。
- 在 SaaS 技术支持场景中，产品可以表现为 B2B；在消费客服场景中，更接近 B2B2C。

MVP 选择 **SaaS 产品技术支持** 作为演示场景，但底层能力保持场景无关。

## 4. 目标用户

### 4.1 客户

需要查询产品功能、API、套餐、账单、服务状态或提交技术问题，希望获得快速、准确且可继续追踪的答复。

### 4.2 客服或技术支持

需要处理 AI 无法解决或风险较高的问题，希望接管时能够直接看到问题摘要、已检索知识、已执行操作和推荐下一步。

### 4.3 管理员或 AI 运营人员

需要维护知识、模型和工具配置，查看 Agent 运行链路，并通过离线评估与线上反馈持续改进效果。

## 5. 用户问题

- 企业知识分散在 FAQ、产品文档和操作手册中，人工检索效率低。
- 通用聊天机器人容易脱离企业知识回答，无法说明答案来源。
- 能调用工具的 Agent 可能误执行创建工单、修改数据等写操作。
- AI 转人工时上下文丢失，客户需要重复描述问题。
- 团队缺少可复现的评估集，无法判断提示词、模型或检索策略是否真的变好。
- 模型、检索和工具调用链路缺少统一追踪，故障难以定位。

## 6. 核心价值

### 6.1 有依据地回答

回答必须来自允许使用的企业知识，并展示引用来源。知识不足时，应明确拒答、追问或建议人工处理。

### 6.2 安全地执行

只读工具可以在授权范围内自动执行；创建工单等有副作用的操作必须经过参数校验、用户确认、幂等保护和完整审计。

### 6.3 平滑地转交

转人工时生成结构化摘要，包含用户诉求、风险信号、检索结果、工具执行记录和建议动作。

### 6.4 可观测、可评估

每次运行记录模型、检索、工作流节点、工具调用、Token、延迟和错误；每次关键改动都能通过固定数据集回归验证。

## 7. 产品差异化

本项目不以“功能数量”作为主要竞争点，而重点展示以下工程能力：

1. 基于 Eino 的可控 Agent 工作流，而不是单次 Prompt 调用。
2. 真正评估知识是否足以回答，而不是只判断是否检索到结果。
3. 写操作 Human-in-the-loop、Checkpoint、Resume 和幂等执行。
4. 面向开发者的运行 Trace 与离线 Eval。
5. 可一键部署、可重试、可审计的生产化闭环。

## 8. MVP 场景

演示企业为一家提供开发者 API 的 SaaS 公司，知识库包含：

- 产品功能说明
- API 接入文档
- 套餐与账单规则
- 常见错误码
- 服务状态和故障处理手册

系统提供两个业务工具：

- 查询客户订阅和套餐信息，只读操作。
- 创建技术支持工单，写操作，必须经过用户确认。

## 9. 成功标准

MVP 完成时应满足：

- 用户可以基于已导入知识获得带引用回答。
- 知识不足时不会编造确定性答案。
- 用户可以查询模拟订阅信息。
- 未经确认不能创建工单。
- 创建工单请求可安全重试，不会重复建单。
- 人工接管时能够看到 AI 生成的结构化摘要。
- 每次 Agent 运行均可查看节点、检索、工具、延迟和 Token。
- 至少建立 50 条可重复执行的离线评估用例。
- 项目可以通过 Docker Compose 一键运行。

## 10. 非目标

MVP 不实现：

- 可视化拖拽工作流编辑器
- 企业微信、钉钉、WhatsApp 等多渠道接入
- 完整多租户计费体系
- 复杂 RBAC、客服排班和组织架构
- 完整 ITSM 工单状态机
- 多数据库和多向量数据库兼容
- 多 Agent 自主协作
- 语音、图片等多模态客服
- 原生移动端

## 11. 简历叙事

项目应能够被概括为：

> 独立设计并实现企业级 AI 技术支持平台，使用 Go、Eino、PostgreSQL/pgvector 和 Next.js 构建 RAG、工具调用、人工确认、转人工、运行追踪及离线评估闭环，并通过持久化任务、幂等和 Docker 化部署提升系统可靠性。

# Agent Chat 开发路线图

## 1. 原则

- 先完成可演示的纵向闭环，再扩展后台功能。
- 每个阶段都必须有可运行结果、测试和文档。
- AI 能力与普通业务能力同时建设，不以页面数量衡量进度。
- 不提前实现非目标中的多租户、多渠道和可视化编排。

## 2. 阶段 0：需求与工程基线

目标：建立统一的产品、架构和开发约束。

交付物：

- 产品简述
- 需求规格
- 用户流程
- 架构设计
- 评估方案
- AGENTS.md
- 初始任务列表

完成标准：

- P0、P1、P2 和非目标无冲突。
- Eino 与领域层边界明确。
- 第一条纵向链路定义清楚。
- 关键技术选择有依据。

## 3. 阶段 1：RAG 纵向闭环

目标：完成“FAQ 导入到带引用回答”的端到端链路。

后端：

- Go/Gin 项目脚手架
- PostgreSQL 和迁移
- FAQ、文档版本和切片模型
- 持久化索引 Job
- Embedding 和 pgvector
- Eino Retriever
- Eino Graph 基础节点
- Answerability Gate
- SSE 事件
- Trace 表

前端：

- 客户聊天页
- FAQ 管理页
- 文档索引状态
- 基础 Run 详情

测试与 Eval：

- 领域单元测试
- Repository 集成测试
- 10 条知识问答 Eval
- 无知识拒答测试

完成标准：

- 从空数据库导入 FAQ 后可以提问。
- 回答流式展示并包含引用。
- 无支持知识时不会生成确定性答案。
- 所有节点可在 Run 详情查看。

## 4. 阶段 2：工具调用与 Human-in-the-loop

目标：完成安全的业务工具调用。

功能：

- 模拟 CRM 订阅数据
- `query_subscription` 只读工具
- 工单草稿生成
- `create_ticket` 写工具
- Eino Interrupt/Resume
- 审批持久化和过期
- 幂等创建工单
- Worker 重试

测试与 Eval：

- 工具路由测试
- Schema 和权限测试
- 确认、取消、重复确认和过期测试
- 20 条工具与审批 Eval

完成标准：

- 订阅查询可以自动执行。
- 创建工单前明确展示草稿。
- 未确认、取消、过期均不会创建工单。
- 重复确认只产生一个工单。
- 服务重启后可以恢复待确认流程。

## 5. 阶段 3：人工接管

目标：实现 AI 到人工的完整协作。

功能：

- 等待人工会话队列
- 客服接管与回复
- WebSocket 实时事件
- 接管摘要
- AI 自动回复暂停与恢复
- 会话状态审计

测试与 Eval：

- 会话状态机测试
- AI/人工并发回复测试
- 主动转人工和策略转人工 Eval

完成标准：

- 客户主动要求人工后进入等待队列。
- 客服接管后 AI 不再自动回复。
- 客服能看到结构化摘要和完整 Trace。

## 6. 阶段 4：Eval 与可观测性

目标：让模型、Prompt 和检索调整可量化。

功能：

- Python Eval Runner
- 60 条黄金数据集
- 检索、回答、工具和安全指标
- Eval 报告页面
- Eino Callback Trace 完善
- Token 和成本统计
- 线上反馈入口

完成标准：

- 一条命令可以运行固定数据集。
- 报告展示基线和回归。
- 安全门槛不通过时 CI/命令失败。
- 可以从失败 Case 跳转到 Run Trace。

## 7. 阶段 5：交付与简历包装

目标：形成可公开演示的工程作品。

交付物：

- Docker Compose 一键启动
- GitHub Actions
- 初始化演示数据
- 架构图和关键决策
- 3～5 分钟演示视频
- 截图和 GIF
- 性能与 Eval 报告
- 简历项目描述

演示脚本：

1. 导入 SaaS API 文档。
2. 回答一个可回答问题并展示引用。
3. 对缺少信息的问题进行追问。
4. 查询客户订阅。
5. 创建工单并展示确认。
6. 转人工并查看接管摘要。
7. 查看完整 Run Trace。
8. 运行 Eval 并展示报告。

完成标准：

- 新环境按照 README 可以在 15 分钟内启动。
- 演示不依赖手工修改数据库。
- 项目首页能够清楚说明问题、方案、架构和指标。

## 8. 推荐迭代顺序

```text
文档基线
  -> 后端脚手架
  -> PostgreSQL/pgvector
  -> FAQ 索引
  -> Eino RAG Graph
  -> SSE 聊天
  -> 引用与 Trace
  -> Answerability Eval
  -> 只读工具
  -> 写工具 + Approval
  -> 人工工作台
  -> 完整 Eval
  -> 部署与演示
```

## 9. 首批任务

文档评审通过后的前十个任务：

1. 初始化 Go module、目录和配置加载。
2. 初始化 Next.js、shadcn/ui 和基础布局。
3. 增加 PostgreSQL/pgvector Compose。
4. 建立数据库迁移机制。
5. 实现知识领域模型和 Repository。
6. 实现持久化 Job Worker。
7. 接入 Eino ChatModel 和 Embedding。
8. 实现 FAQ 索引与 pgvector Retriever。
9. 实现基础 Eino RAG Graph。
10. 实现消息 API、SSE 和最小聊天页面。

## 10. 范围控制

出现以下情况时应停止扩展并回到当前阶段：

- 为了一个演示场景引入第二套数据库或向量库。
- 在 RAG 闭环完成前开发大量管理页面。
- 在单 Agent 工作流稳定前引入多 Agent。
- 在后端节点未稳定前开发可视化工作流编辑器。
- 为追求框架使用量将普通业务逻辑塞入 Eino Graph。
- 没有 Eval Case 就修改 Prompt 或 Answerability 策略。

# Agent Chat 需求规格

## 1. 范围与优先级

需求使用以下优先级：

- `P0`：MVP 必须完成。
- `P1`：MVP 稳定后补充。
- `P2`：长期方向，不进入首版排期。

## 2. 用户角色

### 2.1 客户

- 创建或继续会话。
- 发送问题并接收流式回答。
- 查看回答引用。
- 确认或取消有副作用的操作。
- 主动申请人工支持。

### 2.2 客服

- 查看等待接入和处理中会话。
- 接管会话并发送人工回复。
- 查看 AI 会话摘要、知识命中和工具执行结果。
- 创建、更新和关闭支持工单。

### 2.3 管理员

- 管理知识库、文档和 FAQ。
- 配置模型、Prompt、检索参数和工具白名单。
- 查看 Agent Trace 和 Eval 报告。

## 3. P0 功能需求

### FR-001 知识导入

系统必须支持录入 FAQ 和 Markdown 文档。

验收条件：

- 文档保存后进入持久化索引任务。
- 索引任务支持失败重试。
- 文档更新后旧切片和向量不会继续参与检索。
- 管理员可以看到索引状态和错误原因。

### FR-002 知识检索

系统必须根据用户问题检索相关知识。

验收条件：

- 支持 Top-K 和最低相似度配置。
- 检索结果包含来源、切片、分数和排序。
- 支持元数据过滤。
- 检索过程写入 Trace。

### FR-003 带引用回答

系统必须基于检索知识生成回答并返回引用。

验收条件：

- 引用能够定位到具体文档或 FAQ。
- 回答中没有使用的知识不能标记为引用。
- 配置了知识库时，回答不得绕过知识约束给出确定性业务结论。
- SSE 事件可以区分文本增量、引用、完成和错误。
- 页面刷新后可以从持久化消息和 Graph Result 恢复三类 Answerability 呈现与引用。
- 恢复进行中的 Run 只续订原 SSE，不得重新提交消息或创建新的 Run。

### FR-004 Answerability Gate

系统必须判断当前知识是否足以回答用户问题。

验收条件：

- 输出 `answerable`、`needs_clarification`、`unanswerable` 三类结果。
- 结果包含理由、置信度和支持证据。
- `needs_clarification` 时优先向用户追问。
- `unanswerable` 时拒绝编造，并提供人工支持入口。
- 不能仅以“检索结果非空”作为可回答判断。

### FR-005 订阅查询工具

Agent 必须可以调用模拟 CRM 查询客户订阅信息。

验收条件：

- 工具通过结构化 Schema 定义输入输出。
- 工具只允许读取当前客户授权范围内的数据。
- 参数错误、超时和下游错误返回可解释结果。
- 工具调用写入 Trace。

### FR-006 创建工单

Agent 必须可以根据会话准备并创建技术支持工单。

验收条件：

- Agent 先生成结构化工单草稿。
- 工具规划可以读取当前源消息之前的有限服务端会话历史，以支持多轮排障后的建单请求。
- 用户确认前不得调用创建接口。
- 取消后不得产生任何工单副作用。
- 相同幂等键重复执行只产生一个工单。
- 成功后向用户返回工单编号。

### FR-007 人工确认与恢复

工作流必须支持中断并在用户响应后恢复。

验收条件：

- 中断状态、Checkpoint 和待确认内容持久化。
- 服务重启后仍可继续待确认流程。
- 重复确认不会重复执行写操作。
- 过期确认请求不能继续执行。

### FR-008 转人工

客户可以主动要求人工，系统也可以根据策略建议人工介入。

验收条件：

- 会话状态可从 AI 接待切换到等待人工和人工处理中。
- 转人工后 AI 不再自动回复，除非客服明确恢复 AI。
- 系统生成结构化接管摘要。
- 客服可以看到用户诉求、风险、引用和工具执行历史。

### FR-009 运行追踪

管理员必须能够查看每次 Agent 运行。

验收条件：

- 记录 `request_id`、`conversation_id` 和 `run_id`。
- 展示 Eino Graph 节点路径和每个节点状态。
- 展示模型、Prompt Token、Completion Token 和耗时。
- 展示检索结果、Answerability 决策和工具调用。
- 敏感配置和认证信息必须脱敏。

### FR-010 离线评估

项目必须提供可重复运行的评估工具。

验收条件：

- 评估集使用版本控制。
- 可以针对指定模型、Prompt 和检索配置运行。
- 生成机器可读结果和 Markdown 摘要。
- 未达到安全门槛时命令返回失败状态。

## 4. P1 功能需求

- PDF、HTML 和网页文档导入。
- Rerank 和多查询改写。
- 客服修改 AI 摘要并反馈。
- 客户对回答点赞、点踩和标注错误引用。
- Prompt 与工作流配置版本化。
- 模型成本估算和预算告警。
- OpenTelemetry Trace 导出。
- 管理员回放历史请求。
- 多知识库路由。
- 会话标签和基础统计看板。

## 5. P2 功能需求

- 多租户和租户级数据隔离。
- 多渠道接入。
- 多 Agent 协作。
- 语音和多模态支持。
- 自动生成 Eval Case。
- 基于线上反馈的知识缺口分析。
- 灰度发布与模型 A/B 测试。

## 6. 非功能需求

### NFR-001 安全

- 密钥只能从环境变量或密钥系统读取。
- 所有工具使用显式白名单。
- 写操作必须确认、鉴权、校验、幂等并审计。
- 检索内容按不可信输入处理，不能覆盖系统指令。
- 日志和 Trace 不记录明文密钥。

### NFR-002 可靠性

- 索引和 Agent 后台任务必须持久化。
- 所有外部调用必须设置超时。
- 可重试错误使用有上限的退避策略。
- 服务重启不能丢失待执行任务和待确认流程。
- 关键状态变化必须在事务内完成。

### NFR-003 可观测性

- 所有请求使用统一关联 ID。
- 记录应用耗时、模型耗时、检索耗时和工具耗时。
- 错误日志包含可定位上下文，但不泄露敏感信息。
- 关键业务和 Agent 决策必须可审计。

### NFR-004 性能

- 普通非模型 API 在本地基准环境下 P95 小于 300ms。
- SSE 建连成功后应立即发送运行状态事件。
- 检索、模型和工具分别设置独立超时。
- 文档索引不得阻塞在线请求。

### NFR-005 可维护性

- 业务领域代码不能直接依赖 HTTP、数据库或 Eino 具体实现。
- Eino 只能位于 Agent Runtime 和 AI 基础设施层。
- 前后端 DTO 显式定义，不直接暴露数据库模型。
- 关键状态机、工作流分支和工具必须有测试。

## 7. 数据与隐私

- MVP 使用演示数据，不接入真实客户隐私数据。
- 客户标识、订阅数据和工单数据仅用于本地演示。
- Trace 中的用户输入应支持后续增加脱敏策略。
- 删除知识文档时必须同步停止对应切片参与检索。

## 8. 发布验收

首个公开版本必须满足：

- 所有 P0 功能完成。
- Go 测试、前端 lint/typecheck/build 通过。
- 评估安全门槛通过。
- Docker Compose 从空环境可以启动。
- README 包含架构、演示流程和部署方式。
- 提供至少一个完整录屏或在线演示。
